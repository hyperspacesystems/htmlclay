Changelog

What changed in each release of the HTML Clay desktop app.

November 14, 2026

1.16.4

Added

  • The Kept Copies page lists the copies HTML Clay kept when an outside change removed data from a document, with actions to show a copy in Finder or delete one copy or all copies for a document. Delete All removes only the copies listed on the confirmation page.

Changed

  • The bundled ClayJS runtime is now 1.26.0.
November 14, 2026

1.16.3

Added

  • Host metadata announces data-guard-v2: the data loss guard now tracks typed values and canonical sheet grids across saves and opens, and offers Put it back when data is lost.
  • The data API reads canonical sheet grids, and sheet patches can delete a tab with { sheet, delete: true }.

Changed

  • A program writing through the data API with a matching If-Match header can remove data without raising a loss notice unless 90 percent or more of the values are removed.
  • A program write through the data API that would remove data without If-Match is refused with 428 (read-required) and the current etag.
  • Silent data removal from an outside edit keeps a pinned copy of the replaced version, and a program write answers 503 when that copy cannot be kept.
  • The bundled ClayJS runtime is now 1.25.0.

Fixed

  • Rows cloned by the data API from a hidden cms-template seed element are now visible.
November 12, 2026

1.16.2

Nothing changed in the app in this release.

November 11, 2026

1.16.1

Added

  • HTML Clay checks saves, data API writes and outside edits for data loss, announces data-guard-v1 in /_/meta, and shows a notice bar inside <body> that survives restarts. The notice offers Restore when restoring is possible, and Restore and Revert keep a copy of what they replace, recheck that the folder is trusted, warn about new items added after the loss that restoring would remove, and send the result to every open tab.
  • The data API supports [*] rules to match all elements for a selector.

Changed

  • Saves strip the sitevisibility attribute from <html>.
  • The bundled ClayJS runtime is now 1.24.0.

Fixed

  • Hidden tabs receive live sync updates immediately rather than waiting to be shown, avoiding stale version conflicts on their next save, and silent hidden tabs stay connected for five minutes.
  • Relinking a program whose folder was moved or deleted opens the file picker at the nearest existing parent folder instead of failing on macOS.
November 8, 2026

1.16.0

Changed

  • The bundled ClayJS runtime is now 1.23.0.
November 3, 2026

1.15.1

Fixed

  • Offline copy exports strip no-copy sections.
  • Configured local programs are restored after HTML Clay restarts for an update.
November 1, 2026

1.15.0

Added

  • Setting up a document's program uses one native dialog that shows the file that would run, suggests a match from programs already set up or from folders where you keep programs (matching .exe, .bat or .cmd extensions regardless of case on Windows), and records the file's identity before opening so a file replaced during approval is refused. It never suggests a file from the document's folder, Downloads, a temporary folder, the internet, a file changed in the last ten minutes, or a shell or script interpreter, and choosing one of those by hand asks for confirmation first.
  • Documents with unset programs show a setup bar that starts program setup, which can also be started from a click on the page or from the tray.
  • A Programs page at 127.0.0.1/programs, opened from Manage Programs in the tray, lets you remove a document's access, relink a program whose file moved, or widen a grant through native dialogs.

Changed

  • Opening a document no longer prompts about its programs. Requests for a program that is not set up wait up to two minutes for setup and then fail with helper_setup_expired.
  • The program setup dialog has no default button, so pressing Return does not approve a program.
  • Program grants for any document apply only inside trusted folders, and removing access is remembered and overrides a grant for any document.
  • Manage Programs, Open Documents and relink items for missing program files replace Add a Program and the individual program management dialog in the tray.

Fixed

  • On Windows, the program file picker opens in front of the browser instead of behind it.
  • On macOS, clicking Cancel in a dialog counts as a refusal rather than an error.
October 30, 2026

1.14.1

Added

  • A page's first request to a declared helper program that nobody has answered now opens the permission dialog and waits, instead of failing until the file is reopened.
  • Requests for the same program name share one dialog, and answering a dialog no longer cancels another helper's running request.
  • A new optional data-program-folder attribute on a helper declaration sets where the program picker opens. A value starting with ~/ opens that folder under your home folder from any document, and other values stay relative to the document.
  • The /_/meta/{token} endpoint takes reveal, versions-folder and export actions, so a page can ask HTML Clay to show its file in the file manager, open its versions folder, or zip it into Downloads.

Changed

  • A dialog that grants nothing spaces the next page-raised dialog by a minute per document, and Deny stops page-raised dialogs until the page is opened directly again.
  • HTML Clay no longer advertises live-data or page-room capability to pages.
  • The project is now released under the Competing Service license.

Fixed

  • Assets in a folder that was deleted and recreated under the same name now serve from the new folder instead of answering 404 until the app restarts.
  • A page saved with a compacted v1 page tag reopens byte-identical.
October 27, 2026

1.14.0

Added

  • @--name rules in the data API read and write a single custom property in the style attribute, with the same value checks as the reference; raw @style writes are still refused.
  • Host metadata reports the document save limit the host enforces, and that the host keeps version history, as document.versions.
  • Documents that name a clayjs.com runtime URL are served with those URLs pointing at the bundled ClayJS 1.17.0 runtime at /_/clayjs/.
  • Saves, data writes, restore, export and Clay-Source reads never write a /_/clayjs/ URL, and the disk ETag stays the same.
  • A document that cannot be projected says why in the Clay-Runtime-Unavailable header.
  • Host metadata advertises same-browser presence: page-awareness-v1 and record-awareness-v1, with awareness carried over a broadcast channel scoped to the browser. There is no HTTP presence endpoint.
  • GET /_/page-state/{token}, named in /_/meta/{token}, returns the page state stored with the exact bytes on disk, and page-recovery-v1 tells a client it may retire journaled page work against it.
  • GET /_/page-state/{token} answers 428 without If-Match, 412 for a different ETag, and 404 when no state is stored.
  • Saves carry a clay-page-format marker and an X-Clay-Page-Format capability header, and host metadata advertises page-format-v1.

Changed

  • A page save that would write exactly the bytes already on disk is refused with 409 page-nothing-to-write when the client sends Page-Write: v1; nothing is written.
  • A save that would lower a document's page format floor is refused with 409 page-format-upgrade-required before anything is written, and a relay from a host with a lower capability is refused.
  • A page's Yjs tag survives save and reopen. Serving puts back only the state stored for the exact bytes on disk, and the disk ETag does not change.
  • The bundled runtime keeps an author's own <title> in the head.
  • Documents that name no runtime URL and hold no local runtime address skip projection and canonicalization, so large saves and serves are not parsed for nothing.

Fixed

  • The shipped Journal 1.0.0 and 1.1.0 documents and the current template open, late-load their libraries, languages and fonts, and save and reopen with every outside request refused; old CDN URLs answer with the exact classic builds.
  • Opening a Document, Kanban or blank page for editing works offline: every file the edit boot loads comes from the bundled runtime, and the first edit saves canonical bytes and reopens.
  • A stray </noscript> or </template> inside a template no longer exposes the content that was inside it.
October 23, 2026

1.13.8

Added

  • A document can link /tailwindcss/<name>.css to get a stylesheet built from the classes that document uses, with Tailwind v4.1.17, typography, forms in class mode and the ClayJS ephemeral variant.
  • The Tailwind compiler ships inside the binary and is unpacked on first use, so stylesheets build with no network and the one-file self-update keeps working on Linux and Windows.
  • The stylesheet is built from the page that asked for it, then <name>.html, then <name>.htmlclay, and only from a registered document or one inside an opened folder. The document itself is never modified.
  • Built stylesheets are cached under the config directory by a fingerprint of the compiler and the document's class list. Builds run one at a time per process and finish even if the request that started them drops.
  • A build that fails answers an empty no-store stylesheet and logs the failure once.
  • Paths under /tailwindcss/ that are not .css fall through to the ordinary file handler, so a real ~/tailwindcss/ folder keeps working.
October 22, 2026

1.13.7

Added

  • HTML Clay advertises the page extension, so editors mount a writable Yjs page on this host.

Changed

  • Saving a document that holds a converted page with a hybrid, mixed or missing page capture is refused with the same error codes as hosted Hyperclay, and nothing is written.
  • A hybrid page converts only with a valid source=file Page-Conversion header and one current If-Match stamp.
  • Saves and data writes no longer store the editor's merge="page" tag. Open tabs keep sharing the page through their tab-hosted room, and a fresh open rebuilds the page from its article.
  • A save without the merge="page" tag counts as an outside edit, and a stored page document saved with its tag is an ordinary save rather than a first conversion.
October 17, 2026

1.13.6

Added

Fixed

  • An empty attribute reads as "", and writing null removes it. The data API matches ClayJS again: a present but empty attribute such as Kanban's data-done="" used to read as null and could not be written back.

1.13.5

October 15, 2026

1.13.4

Added

  • HTML Clay updates itself on Windows and Linux. A background check verifies a signed update feed, downloads and stages the new version, and the tray row becomes Restart to Update.
  • On macOS, HTML Clay updates itself through Sparkle. The tray offers Restart to Update once the update is ready, and falls back to the download link when Sparkle is missing or cannot update this copy.
  • An update restart keeps saves and open tabs. Every open document comes back at the address it had, with its save token and grants, and a write that arrives during the restart is answered with a retry.
  • An update that fails to start puts the previous version back. That version is skipped from then on, and the open sessions move back with it.
October 14, 2026

1.13.3

Changed

  • Folder addresses are htmlclay, htmlclay1, htmlclay2, and the default port is 1212. The 1.13.1 addresses, such as notes-3f2a.localhost:24190, become htmlclay.localhost:1212, htmlclay1.localhost:1212 and so on, in the order folders are first served. The move happens once, on the first launch of this version; bookmarks to the 1.13.1 addresses stop working and page data stored in the browser under them starts over.

1.13.1

Added

  • One port, an address per folder. HTML Clay serves every folder from one port, 1212 unless it is taken, at an address such as http://htmlclay.localhost:1212/. The address is chosen once per folder and never changes, so bookmarks survive restarts and opening a file again lands on the same page data. If another program holds the port at launch, a dialog names it and offers to quit it, move HTML Clay to a new port, or quit.

Changed

  • Old 127.0.0.1:<port> bookmarks redirect to the new address while their port is free. Browser storage written under an old address does not carry over; the first launch says so once.
  • htmlclay wire takes --origin for an HTML Clay address; --port is for Hyperclay Local.
  • Links between folders work under the default referrer policy; a page that sets no-referrer cannot link to another folder.
  • The format is called a malleable document in HTML Clay's own copy, with the old name left in addresses, identifiers and history.

Note

  • Downgrading to 1.13 drops port, siteSlugs and retiredSlugs from config.json on its next save (unknown fields are discarded), so the addresses are chosen afresh on the next upgrade.

Fixed

  • A double-clicked file or a Start on Login launch no longer opens a terminal window on Windows. htmlclay wire still prints in a terminal.
  • PowerShell dialogs, the browser launch and an AI editing agent no longer open console windows of their own on Windows.
  • Dialogs and prompts come to the front on Windows, including the error a forwarded open shows and the Trust this folder prompt, which now uses the real button labels.
  • Trust a Folder on Windows opens the modern Explorer-style picker, a browser navigation to a path outside the folder gets a plain 403 page instead of a read prompt naming the page, and Stop Trusting labels its refusing button Cancel.
  • A save on Windows replaces a file another program has open.
  • Exporting a file confirms the zip with an ordinary notice, and says something only when the Downloads folder cannot be opened.

September 28, 2026

1.10.0

Added

  • POST /_/api/<file> writes JSON into a document. The body is applied through the page's own api rules tag, the same map GET /_/api reads with, and only content is written: text as text, and attributes that cannot run script. Only the changed elements are rewritten, so every other byte of the file stays as it was. The write is versioned and reaches open tabs like a save. A local program needs nothing extra, and a browser page must send the file's Save-Token.
  • The data API sends an ETag, and a write carrying If-Match is refused with 412 when the file changed since it was read.
  • Trusted folders stay trusted across a macOS reboot. Folders are pinned by volume and inode rather than by the device number macOS renumbers on mount, and a trusted folder whose folder is gone answers with a page saying it needs approving again.

Changed

  • The document-programs prompt no longer remembers a refusal. Deny, Return, Escape, closing it or letting it time out applies to that open only, and the next double click asks again. Refusals stored by earlier versions are dropped. If exactly one program with that name is allowed for any document, a document that refused it now uses it without asking. The prompt shows the program path behind each name and asks which one when several share a name.
  • no-data and editor-ui regions are invisible to the data API, on reads as well as writes, matching hyper-html-api.
  • A browser page proves it holds the file's Save-Token before the data API looks the file up, and every failure answers the same way, so a page cannot tell a missing file from one it may not write. A write against a read-only rule answers 400.

Fixed

  • Data API writes land in documents that start with a byte order mark, and in SVG or MathML markup, whose camelCase names now pair case-insensitively.

August 30, 2026

1.9.0

This release makes HTML Clay speak the Malleable HTML File protocol: it announces what it can do, stamps what it stores, and refuses a save that would land on top of someone else's. It is also the compatibility half of a change in the client libraries, so read the first entry below before upgrading either side.

Changed

  • The save token is injected under both names, savetoken and htmlclaytoken. savetoken is the name spec §9 gives it and the only name ClayJS 1.2.0 and HyperclayJS 1.38.0 read. 1.8.0 and earlier injected only htmlclaytoken, so a document served by an older HTML Clay looks editable to a current client and every save fails. Upgrading to 1.9.0 is the fix for every document at once, and serving both names means a document opened in an older client keeps working too.
  • A document's durable identity is written as documentid. htmlclayid was a product name in a file format that outlives the product. The old spelling is still recognised and removed on save, so a document written by an earlier version is not left carrying two identities.
  • The 415 on a save that is not a document answers unsupported-type. It was unsupported-media-type, which is in the spec's registry nowhere; the upload route already answered the registered name.
  • The six-tab limit is gone. It was a browser limit the host documented as unfixable; the shared stream under Added and the matching ClayJS client integration are the fix.

Added

  • One live-sync stream for every tab. The /_/sync stream now carries any number of documents and lanes at once, listed as s=lane:since:document-url, each resuming from its own position, and the host serves a small worker at /_/sync/worker.js through which every tab on the origin shares that one stream. A browser allows six connections per origin and each tab used to hold one for the life of the page, so the seventh tab of one project never loaded. With ClayJS shared-worker support, tabs share one connection. The one-document spelling still works for documents that vendor an older runtime.
  • The sync-worker compatibility marker identifies workers that preserve separate peer and disk updates across notifications and invalidate cached content after a replay gap. Clients can keep the direct transport on older hosts.
  • The wire stream opens with a cursor for pages, so a page whose stream drops before any frame arrives can still resume from a position rather than from nothing. Processes tailing the wire receive no cursor.
  • /_/meta discovery. A page can ask what the host supports rather than probing for it: the protocol version, the two scopes, and the capability list, which on this host is conditional, receipts, sync and upload. format is deliberately absent: this host stores the bytes it was sent, so it ignores formathtml entirely, and §4 says a host that does not declare format is telling every client exactly that. The document block is withheld by omission rather than by an error, per §5.

  • Save receipts. A save may carry a Save-ID, an opaque id a client mints for that one attempt, and this host remembers which id belongs to the bytes it currently stores. It reports that id as saveId in /_/meta, on every accepted save, and on every 412. A client whose save timed out can then ask the one question it cannot answer alone, whether its own write is what landed, instead of guessing and either overwriting somebody else's work or showing a conflict notice over a few seconds of bad wifi.

    The id is remembered beside the stamp of the bytes that save wrote and is reported only while that stamp still matches what is on disk. So a write from anywhere else, a text editor, a git checkout, an agent on the filesystem, invalidates it by moving the bytes, with nothing having to notice. An id is never minted here and never accepted as authorization for anything; the host only ever echoes what a client sent.

  • Conditional saves. Every save answer carries an etag, and a save sent with If-Match is refused with 412 and a conflict code, nothing written, when the document changed underneath it. The stamp is computed over the bytes on disk rather than over the bytes the host was sent, since those differ whenever a host normalises and stamping what was sent would tell a client its disk holds something it does not.
  • changedBy on the conflict refusal, naming what moved the file when the host actually knows (another-tab, another-person, an-agent) and omitted when it does not. A host must not guess: a plain filesystem write has no author.
  • The live-sync relay forwards etag on the editor lane. The saving browser sends the stamp along with the bytes it just saved, so a receiving tab adopts a stamp only as part of applying the content that stamp describes. The viewer lane drops it, since a viewer holds a whole document rather than a pre-strip snapshot and has no save to condition.
  • A disk change carries the stamp of the bytes it delivers. When the watcher sees a file edited outside the browser, the notification it sends the editors now carries that version's etag alongside the content. A tab used to apply the change and then ask /_/meta for a replacement stamp, which answers about whatever is stored at that later moment: if a second write landed in between, the tab adopted a stamp for bytes it had never seen and overwrote them on its next save. The stamp is taken from the bytes on disk rather than from the rendering sent to the browser, so it matches what a later If-Match is compared against. The viewer lane still carries no stamp.
  • A favicon, so an opened document is identifiable in a row of tabs.
  • The protocol conformance page ships with the host (testdata/conformance/) and runs in CI on every push, so a release cannot quietly stop conforming.
  • website/llms.txt, a full reference for agents reading the site.

Fixed

  • A refusal the host answers itself carries a readable msg, and invents no code outside the spec's registry. The 409 on a truncated write used to answer a conflict code, which reads to a client as a stale-stamp conflict it can retry past, rather than as a write it must not repeat.
